SEED PROMPT — SUPERMEGA PIXEL GARDEN
====================================
You are implementing the "pixel garden" visual system from
https://experiments.supermega.design/pixel-garden/ in the user's project.

WHAT IT IS
A retro pixel-art scene system drawn on HTML canvas. Everything derives
from one metric: a 4px grid where each cell is a 3x3px square with a 1px
gap. Sprites (flowers, trees, suns, letters) are ASCII maps that grow from
the ground up, cell by cell, like construction — never fading in.

CORE RULES (reimplement these, or fetch the engine below)
- GRID = 4 (cell pitch), PX = 3 (square size). snap(v) rounds to the grid.
- A sprite is { rows: ["..F..", ".FFF.", ...], stemCol, pal: { F: "#hex" } }.
  Each character indexes a palette color; "." is empty. stemCol anchors
  the sprite to its ground x. Vertical anchor: spriteCells puts the
  bottom row one grid cell ABOVE groundY (y = groundY - (rows - r) * cell),
  so set groundY to the top of your soil strip.
- spriteCells(sprite, scale, groundX, groundY) flattens rows into cells
  ordered bottom-to-top — stem first, petals last — so growth reads as
  planting, not printing.
- Grower(cells, { bornAt, duration }) reveals floor(eased * cells.length)
  cells per frame. Ease is expo-in WITH CLAMPS AT BOTH ENDS:
  t <= 0 ? 0 : t >= 1 ? 1 : Math.pow(2, 12 * t - 12), and clamp the input
  with Math.min(1, age / duration). Unclamped it indexes past the cell
  array and crashes. Fully grown sprites flicker: hide 3 pseudo-random
  cells every 100ms (a building that hums after the crew goes home).
- Respect prefers-reduced-motion: render everything fully grown, skip
  the flicker and any cursor trails. A grow-in animation is exactly the
  case that needs this.
- Determinism: seed all randomness from an fnv-1a hash. The engine's
  PG.rng(seed) accepts a string or a number; if you write your own
  number-only rng, call it as rng(fnv("key")).
- Scene layers. Pre-render the static stack to an offscreen canvas once
  per resize, in this order: sky fill + halftone dot texture, pixel sun
  (two-tone disc + an 8-ray ring, 3 dots per ray), background ridges /
  mountains, meadow band, soil strip. Then every frame draw: the static
  canvas, the drifting lobed clouds ON TOP of it, then the growing
  sprites. Clouds come after the ground layers, not before.
- Dithered fills are a HUE trick, not a value trick. 3x3 squares on a
  4px grid cover 56%, so 44% of the background mixes through every
  dithered mass. That separation survives only when layers differ in hue
  (green meadow on cream sky). On a low-hue-contrast brand palette
  (monochrome browns, all-blue, etc.) large dithered grounds collapse
  into mud — fill big ground masses SOLID and lay sparse pixel grain on
  top; keep the dot-matrix texture for sky, sun, clouds, and sprites.
- Scale responsively: tie sprite scale, band heights, and ridge
  amplitude to viewport width (and min(width, height) for ridges), or
  phones get viewport-sized plants.
- image-rendering: pixelated; ctx.imageSmoothingEnabled = false; multiply
  canvas buffer sizes by devicePixelRatio.
